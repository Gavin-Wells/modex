# ModelSwitch integration preview

This checkout starts from Eigent main at b764e42bd8a4542cbb237dd45436c172f96e747b. The top bar offers a ModelSwitch terminal for an already installed Claude Code or Codex CLI. The user selects a project folder, enters a ModelSwitch key, and launches the selected tool. Closing or ending the session disposes the terminal. Keys are passed to the child environment, not command arguments or shell history, and are not saved by this integration.

The existing OpenAI-compatible model configuration is prefilled with the ModelSwitch endpoint. The packaged desktop application starts and supervises a bundled local workspace service; the old upstream OAuth and hosted deployment integrations are disabled. Other inherited integrations and network destinations still require an audit before production release.

This is not a production release: automatic CLI installation, balance, self-check, feedback, updater validation, Windows CLI launch, and a full Mac GUI test remain to be implemented or verified. User configuration, credentials, browser profiles, memory and journal use `~/.modex`; task files use `~/modex`. Some inherited tooling binaries and virtual environments still use `~/.eigent` and need isolation. Claude Code and Codex both require a separate installation. The web preview cannot launch native terminals.

The design keeps task history and workspace data on each user's computer and authenticates against the existing ModelSwitch account service. The login UI and local service verify ModelSwitch accounts and map their IDs to separate local users. The legacy auto-login and upstream account SDK have been removed. These paths have automated tests with mocked account responses; end-to-end login and Turnstile have not yet been validated in the packaged Mac client. The bundled workspace uses SQLite and a supervised local Redis-compatible service. Storage paths and task data still need a complete per-account isolation audit. Workspace history is not sent by the account verification requests.

Packaged builds require a managed workspace service endpoint from the desktop process. The local bootstrap, SQLite backup on migration, service supervisor, and challenge-response have been tested together on Linux, including with the Python runtime relocated to a path containing spaces. CI checks startup and the login screen in each packaged macOS architecture; a full desktop workflow still requires verification. The client refuses to send login credentials to a fixed local port. Development builds still use the Vite proxy.

UI uses Eigent's Dialog, Button, Input, Select and DsText primitives with semantic spacing. The terminal uses Eigent's existing terminal screen and the existing fixed terminal viewport; Chinese text is currently not localized. Automated checks cover the launch options and the dialog's selection/start/disposal flow. Light/dark visual review, zoom, keyboard navigation, and narrow desktop windows have not yet been checked.
